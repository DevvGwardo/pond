# Shopify Capsule Feature — Notes

## What was added

A token-based Shopify-connected capsule capability for Pond. A capsule can call
`ctx.shopify.graphql()` to query the Shopify Admin GraphQL API using a Custom
App access token — no OAuth, no Partner registration required.

## How to test with a REAL store

1. Open your Shopify admin → Settings → Apps and sales channels → Develop apps.
2. Click "Create an app" (or use an existing Custom App).
3. Under "Admin API integration", click "Configure" and select the scopes you need
   (e.g. `read_products`).
4. Copy the Admin API access token.
5. Scaffold a capsule:
   ```bash
   pond new my-shop --template shopify
   cd my-shop
   npm install
   ```
6. Edit `.env.pond.server`:
   ```
   SHOPIFY_SHOP=my-store.myshopify.com
   SHOPIFY_TOKEN=shpat_abc123...
   ```
7. Run `npm run dev`.
8. Open `http://localhost:3000` — you should see your products listed.
9. To test the error state, remove the env vars and restart — you should see
   a styled error box with setup instructions.

## How the deploy path works

Shopify capsules deploy through the existing host unchanged. The env vars flow
through `pond env set`:

```bash
pond deploy --api <host-url>
pond claim <deployId>
pond env set <deployId> SHOPIFY_SHOP=my-store.myshopify.com
pond env set <deployId> SHOPIFY_TOKEN=shpat_abc123...
```

**Important:** Shopify capsules require an **authenticated (claimed)** deploy.
Anonymous deploys block all outbound `fetch` by design (`installNetworkRestriction()`
in `src/host/deploy-worker.ts`). The anonymous sandbox was NOT weakened.

## Key design decisions

- **Token model, not OAuth.** No embedded Shopify Partner app flow. The merchant
  creates a Custom App in their admin and pastes the token.
- **No new npm dependencies.** Uses global `fetch` (Node 18+) and Node built-ins.
- **Capsule contract unchanged.** `server/index.ts` still imports only from
  `pond/server`. No arbitrary npm deps.
- **Shop domain normalization.** Accepts `my-store`, `my-store.myshopify.com`,
  `https://my-store.myshopify.com/` — all normalize to `my-store.myshopify.com`.
- **API version.** Defaults to `2025-01` (current stable). Override via
  `SHOPIFY_API_VERSION` env var.
- **No token logging.** The `graphql()` implementation never logs the token.
- **Template style.** Follows Pond's house style: bg-black, neutral palette,
  square corners, wireframe buttons, tabular-nums, mono metadata.

## Open questions / assumptions

- The test imports `createShopify` from the compiled `src/runtime.js` export.
  This is the same pattern used by `test/deploy-worker-egress.test.mjs`.
- `SHOPIFY_API_VERSION` default `2025-01` was chosen as the current stable
  version at time of writing. Update it as Shopify releases new versions.
- The template uses a products-first approach because it's the most common
  Shopify API use case. Future templates could target orders, inventory, etc.
- The "authenticated deploy required" constraint is documented but not enforced
  at compile time — a Shopify capsule will fail at runtime if deployed
  anonymously. This is intentional: the same outbound-block applies to ANY
  capsule that uses `fetch`, not just Shopify ones.
